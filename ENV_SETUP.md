## Quick answers (from code)

### Is `GOOGLE_CLIENT_SECRET` required?

**No.** It is **not referenced anywhere** under `backend/src` or `frontend/src`.

Google auth uses only:

```js
// backend/src/services/googleAuthService.js
const client = new OAuth2Client(env.googleClientId);
ticket = await client.verifyIdToken({
  idToken,
  audience: env.googleClientId,
});
```

That path needs the **OAuth client ID** as the ID-token audience — not a client secret. Client secrets are for server-side OAuth code exchange; this API verifies a mobile/web **ID token**.

### Can my existing Android Google OAuth client be reused?

**Yes, if** the ID tokens your Android app sends to `POST /auth/google` have an `aud` claim equal to the value you put in backend `GOOGLE_CLIENT_ID`.

This backend checks a **single** audience:

```js
audience: env.googleClientId  // from process.env.GOOGLE_CLIENT_ID
```

| Situation | What to do |
|-----------|------------|
| Android already uses Google Sign-In with Client ID `X` | Set `GOOGLE_CLIENT_ID=X` on the backend (same Android client ID). |
| You only have a **Web** client ID today | Create/use an **Android** OAuth client in Google Cloud for the app package + SHA-1; set backend `GOOGLE_CLIENT_ID` to that Android client ID (or whatever `aud` your app’s ID tokens actually carry). |
| Admin console Google login | **Not used.** Admin auth is email/password (`POST /admin/auth/login`), not Google. |

You do **not** need a new client solely because of a “client secret” — this stack never reads `GOOGLE_CLIENT_SECRET`. You only need a new client if your current token’s `aud` cannot match what you configure on the server.

## 2–5. Every environment variable (from code)

### Backend — required at process start

Source of truth: `backend/src/config/env.js` `REQUIRED_VARS` (L5–17). Missing any → process exits.

| Variable | Service / purpose | Where to create | Where to place |
|----------|-------------------|-----------------|----------------|
| `MONGO_URI` | MongoDB Atlas (or local Mongo) | [MongoDB Atlas](https://cloud.mongodb.com/) → Cluster → Connect → Drivers | `backend/.env`; production secret store (Render/Railway/Fly env UI, etc.). **Not** Vercel frontend. |
| `JWT_SECRET` | Self-generated HMAC secret (mobile access JWT) | Generate with a CSPRNG (e.g. `openssl rand -hex 32`) | `backend/.env` / host secrets |
| `JWT_REFRESH_SECRET` | Self-generated (mobile refresh JWT) | Same | Same |
| `ADMIN_JWT_SECRET` | Self-generated (admin access JWT); **must ≠** `JWT_SECRET` | Same | Same |
| `ADMIN_JWT_REFRESH_SECRET` | Self-generated; **must ≠** `JWT_REFRESH_SECRET` | Same | Same |
| `GOOGLE_CLIENT_ID` | Google Cloud OAuth client ID (ID token audience) | [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials → OAuth 2.0 Client ID | `backend/.env` / host secrets |
| `TWILIO_ACCOUNT_SID` | Twilio | [Twilio Console](https://console.twilio.com/) | `backend/.env` / host secrets |
| `TWILIO_AUTH_TOKEN` | Twilio | Twilio Console | Same |
| `TWILIO_PHONE_NUMBER` | Twilio sender number | Twilio Console → Phone Numbers | Same |
| `ADMIN_ORIGIN` | CORS allow-list for admin UI (comma-separated; never `*`) | You define (e.g. `http://localhost:5173`) | `backend/.env`; production = deployed admin origin(s) |
| `CERT_SIGNING_PRIVATE_KEY` | Server Ed25519 private key (PEM; `\n` escaped OK) | `cd backend && npm run generate:cert-keypair` | `backend/.env` / host secrets — **never commit** |

```env
# From: npm run generate:cert-keypair  (use \n for newlines)
```

### Android — example only (names are conventional; **not defined in this repo**)

```properties
# local.properties (machine-local; do not commit secrets if you put them here)
# sdk.dir=...

# Suggested BuildConfig / secrets (YOU choose names — this repo does not declare them):
# API_BASE_URL=http://10.0.2.2:5000
# GOOGLE_WEB_OR_ANDROID_CLIENT_ID=<same value as backend GOOGLE_CLIENT_ID>
# CERT_SIGNING_PUBLIC_KEY_PEM=-----BEGIN PUBLIC KEY----- ...
```

The Android app must:

1. Obtain a Google **ID token**.  
2. `POST /auth/google` with that token.  
3. Complete phone OTP via `POST /auth/verify-phone`.  
4. Embed the **public** cert key from `npm run generate:cert-keypair` for offline verification (per script comments).
